# 如果我是教授：A grade 要咩，同 10 個可行方向

> 這份文件回答三條問題：
> 1. 從評審角度，邊個 level 值咩分？
> 2. 在此基礎上，10 個你可以做的方向（含 gap 證據、指標、難度）
> 3. 我最推薦的 5 個，以及為什麼

---

## 一、評分表（教授視角）

| 維度 | 權重 | C（合格 60–69） | B（好 70–79） | A（優異 80+） |
|---|---|---|---|---|
| **問題定義** | 15% | 題目清楚，但只是「做一個系統」 | 有明確 gap，引用 2–3 篇文獻 | gap 有**可驗證的證據**（例如：35 篇中有 0 篇處理 X） |
| **文獻與定位** | 15% | 羅列相關工作 | 有比較表，說明異同 | 指出**整個領域的共同盲點**，並解釋為何沒人做 |
| **方法深度** | 25% | 串 API + 模板 | 有自訂模組與工程設計 | 有**可形式化的機制**（指標、演算法、協定），不是 prompt 堆疊 |
| **評估嚴謹度** | 25% | 幾個例子 + 主觀評論 | 有 baseline + 小規模測試 | **2 個以上 baseline、held-out set、消融實驗、人評 n≥30、統計檢定、成本/延遲** |
| **貢獻與洞見** | 10% | 一個能跑的 demo | 一個可用的工具 | 一個**可推廣的發現**（例：「修復迴圈對 overflow 有效，但對重疊無效，因為⋯」） |
| **報告與可複現** | 10% | 有報告 | 結構完整、圖表清晰 | 程式碼、資料、prompt、log 全公開；他人可重跑 |

### 一句話總結

> **B = 你做到了。A = 你證明了，而且別人可以重做一次得到同樣結論。**

## 二、A grade 的六個硬指標（缺一即掉級）

1. **一句話 gap**，而且有文獻證據支撐（不是「我覺得」）。
2. **一個自己定義的東西**：新指標、新資料集、或新評測協定。三者任一。
3. **兩個 baseline** + held-out set + 至少一組**消融實驗**。
4. **人評 n ≥ 30**（pairwise 比較優於絕對評分），或明確的統計檢定。
5. **成本與延遲數字**（token、$、秒/版）。2026 年的評審一定會問。
6. **公開 artifact**（repo + 資料 + 評測腳本）。這是最便宜的加分位。

## 三、從 35 篇反推：A 級論文長什麼樣

| 論文 | 它做對了什麼 | 你可複製的模式 |
|---|---|---|
| **Paper2Poster** | 不問「好不好看」，而問「讀者能不能從成品回答論文問題」（PaperQuiz） | 用**任務表現**代替**主觀評分** |
| **PosterMELD** | 定義 Print-Ready Rate：幾何／可讀性／資產完整／事實錯誤，四個確定性 gate | 把「能用」變成**可數比例** |
| **SlideLab** | 77% 盲測偏好 + 1/4 token 用量 | **效果 + 成本**同時報 |
| **PPTBench** | 用 958 個真實 PPTX 揭示「讀得懂但排不好」 | 用**大規模實證**支撐 gap |
| **Script-to-Slide** | 把題目縮到「script 句子 → slide 物件」，F1 0.924 | **窄而深**勝過大而全 |
| **PresentBench** | 嫌 holistic 打分太粗，改做細粒度 rubric | 改良評測本身就是貢獻 |

**共同點**：它們的貢獻都不是「系統更大」，而是「**定義更清楚**」。

## 四、10 個可行方向

> 難度：1 = 容易，5 = 極難（單人 20 週標準）
> 「文獻證據」欄指的是我在 35 篇全文掃描中實際找到的東西。

### D1. SlideQC：可計算的版面違規指標 + 修復閉環 ★

- **一句話**：定義一套 slide 版面違規的分類與計算方法，並用它驅動修復迴圈，報告「修復前後違規下降幾 %」。
- **文獻證據**：ReDeck 做「逐步修」但**沒有定義度量**；PosterMELD 的 PRR 只針對海報；35 篇中 0 篇提供 slide 版的 violation metric 套件。
- **交付物**：`slideqc` Python 套件（6 類偵測器：overflow / overlap / off-canvas / 對比度不足 / 字級過小 / 圖文碰撞）＋ 修復 agent ＋ 標註資料 150 版。
- **主指標**：違規偵測 precision/recall（對人手標註）、每份 deck 違規數下降百分比、修復成功率。
- **難度**：2 ／ **單人可行**：高 ／ **A 級貢獻**：新指標 + 新資料 + 消融（逐類違規分開報）。

### D2. Claim–Evidence 接地：每條 bullet 都可追溯

- **一句話**：為每條 bullet 生成「來源錨點」（論文頁碼 + 句子 span），並分類 supported / partial / unsupported，量化幻覺率。
- **文獻證據**：SlideBot 有檢索但無錨點；ArcDeck 有 discourse 但無逐句溯源；brief 第 5 點明寫要「check factual support」。
- **交付物**：錨點抽取器 + 支撐度分類器 + 300 條人手標註。
- **主指標**：錨點準確率、unsupported 比例、人手標註 F1。
- **難度**：3 ／ **單人可行**：高 ／ **A 級貢獻**：可量度的事實性 + 新資料集。

### D3. Speaker Notes 2.0：時間預算 + 轉場 + 口語化 ★

- **一句話**：把 speaker notes 從「bullet 的複述」升級為「可直接照讀的講稿」，含每頁時間預算、轉場句、避免照讀 bullet 的提示。
- **文獻證據**：35 篇中只有 5 篇提到 speaker notes，且全部是附帶提及；**0 篇把它當研究對象**。DeepSlide 碰到 delivery 但那是整套系統。
- **交付物**：notes 生成器 + notes 品質 rubric + 30 人評估。
- **主指標**：notes 與 bullet 的重疊率（自動）、時長誤差（自動）、可講性評分（人評）。
- **難度**：2 ／ **單人可行**：極高 ／ **A 級貢獻**：人評 + 成本極低，最容易做出「完整故事」。

### D4. Accessibility-First 簡報生成 ★

- **一句話**：把 WCAG 2.2 AA 的無障礙要求（對比度 ≥4.5:1、字級下限、alt text、色盲安全調色盤、閱讀順序）變成生成的硬約束，並量測其代價。
- **文獻證據**：35 篇全文掃描——**WCAG 出現 0 次**；colorblind 僅 1 次（TalkToYourSlides 附帶）；alt text 僅 3 次且非核心。**零篇以此為研究問題。**
- **交付物**：約束求解器 + a11y 檢查器 + 與無約束版本的對比實驗。
- **主指標**：WCAG 通過率、視覺品質（人評，驗證「無障礙是否犧牲美觀」）、色盲模擬下的可讀性。
- **難度**：3 ／ **單人可行**：高 ／ **A 級貢獻**：novelty 最高、社會意義強、極易講故事。

### D5. 受眾條件化生成系統（用 X+Slides 報數）

- **一句話**：同一篇論文，分別為「專家」與「決策者」生成不同深度的 deck，並在 X+Slides 上評測。
- **文獻證據**：X+Slides 只是 benchmark，**沒有對應的系統**；SlideLab 有受眾概念但未針對該 benchmark。
- **交付物**：受眾感知的內容選擇與深度控制模組。
- **主指標**：X+Slides 四指標（Audience Coverage 等）。
- **難度**：3 ／ **單人可行**：中高 ／ **A 級貢獻**：有現成 benchmark 背書，說服力強但 novelty 中等。

### D6. 雙語（中／英）paper-to-slide benchmark ★

- **一句話**：建立 50 篇中文論文 + 人工 deck 的評測集，並處理中英混排、字體、以及**粵語 speaker notes**。
- **文獻證據**：35 篇全部以英文論文為對象；掃描顯示 multilingual/Chinese 的提及都只是限制說明或翻譯附註，**無一篇做非英文場景**。
- **交付物**：雙語資料集 + 雙語評測協定 + baseline 結果。
- **主指標**：資料集規模與標註一致性（κ）、跨語言品質差距。
- **難度**：4（人手標註重）／ **單人可行**：中 ／ **A 級貢獻**：資料集貢獻最硬，且具地域獨特性。

### D7. 原生 .pptx 的逐步編輯（保持可編輯性）

- **一句話**：在 python-pptx 物件層做 shape 級編輯，每一步都可驗證、可回滾。
- **文獻證據**：SLIDEFORGE / EditPPT 剛開這個方向，但依賴 COM 或 state graph，工程極重。
- **難度**：5 ／ **單人可行**：低 ／ **建議**：只做局部（例如「只改文字、不動版面」）。

### D8. 論文圖表重繪成可編輯向量圖

- **一句話**：把點陣圖 figure 重繪為可編輯形狀（呼應 ReFigBench）。
- **文獻證據**：ReFigBench（2609.18844，未入選 30 篇但相關）剛提出此任務。
- **難度**：5 ／ **單人可行**：低 ／ **建議**：風險太高，不建議。

### D9. 成本–品質 Pareto 曲線

- **一句話**：系統性量測「多少 token / 多少迭代」換多少品質，找出最佳工作點。
- **文獻證據**：SlideLab 報 1/4 token、ACE 報省 89%，但**無人做系統性的 Pareto 分析**。
- **難度**：2 ／ **單人可行**：高 ／ **A 級貢獻**：工程型貢獻，容易做但 novelty 較低。

### D10. 演講排練教練（rehearsal coach）

- **一句話**：根據 notes 與實際講稿，給出節奏、冗餘、遺漏的回饋。
- **文獻證據**：DeepSlide 觸及 delivery 但不做練習迴圈。
- **難度**：4（需語音）／ **單人可行**：中 ／ **建議**：可作 stretch goal。

## 五、最推薦的 5 個

排序依據：**A 級價值 × 單人可行度 × 與 brief 的契合度**

| 排名 | 方向 | 為何推薦 | 最大風險 |
|---|---|---|---|
| **1** | **D1 SlideQC** | 直接對應 brief 第 5 點「inspect」；有明確 gap（ReDeck 只修不量）；指標可客觀驗證；工程量可控 | 人手標註 150 版需時約 3 週 |
| **2** | **D3 Speaker Notes 2.0** | 零篇以此為研究對象；成本極低；人評天然合理（「你能照著講嗎」） | 人評設計要嚴謹，否則被視為 subjective |
| **3** | **D4 Accessibility-First** | WCAG 出現 0 次，novelty 最高；有國際標準可依；社會意義易講 | 可能被質疑「不是 AI 貢獻」→ 要用約束求解回應 |
| **4** | **D2 Claim–Evidence** | 直接回應 brief 的「factual support」；可量化幻覺率 | 錨點標註耗時；跨欄排版論文難處理 |
| **5** | **D6 雙語 Benchmark** | 資料集貢獻最硬；地域獨特；一人可做但需勤力 | 50 篇人工 deck 的工作量被低估 |

### 為什麼不是 D5 / D9

- **D5（受眾）**：benchmark 已存在，你只能做「系統」，novelty 有限，且 X+Slides 的指標設計已定，你難以展現方法論貢獻。
- **D9（成本）**：容易做，但評審會說「這是工程優化，不是研究」。

## 六、我建議的組合包（不要做 5 個，做 1+1+1）

> 單人 20 週，**一個主線 + 一個副線 + 一個 stretch** 是上限。

```
主線（60% 時間）：D1 SlideQC
  └─ 可計算的版面違規指標 + 修復迴圈
  └─ 這是你論文的方法論核心，也是「別人沒做」的部分

副線（25% 時間）：D3 Speaker Notes 2.0
  └─ 接在同一個 agent 上，成為人評的載體
  └─ 提供「除了版面，內容交付也能量度」的第二支柱

Stretch（15% 時間，做唔完就砍）：D4 Accessibility
  └─ 作為約束模組插入，只需報「加了約束後違規率與人評變化」
```

### 這個組合的論文故事線

> 「現有系統能生成好看的 deck，但**不知道自己在哪裡壞了**。我們提出一套可計算的版面違規指標（SlideQC），把它嵌入生成—檢查—修復迴圈，並用 150 版人手標註驗證；配合講稿品質的量化，我們證明：**可量度的檢查比更大的模型更能提升成品可用率**。」

這條故事線同時滿足：
- brief 第 5 點（agent loop + inspect）
- A grade 的六個硬指標
- 單人可完成的工程量

## 七、直接回答「code 可以用 AI 寫」

**正確，而且這正是你的優勢——但也是你的陷阱。**

- 優勢：你不需要花 3 個月學 python-pptx。GPT/Claude 兩日可以給你一個能跑的 renderer。
- 陷阱：**評審也知道這一點**。所以「我用 AI 寫了一個系統」在 2026 年等於零分貢獻。

**你的護城河只有三樣，全部與寫 code 無關：**
1. **人手標註的 ground truth**（150 版違規標註、30 人評分）—— AI 不能替你標。
2. **實驗設計**（baseline 選擇、消融、統計）—— AI 可以建議，但你要負責判斷。
3. **問題選擇**（為什麼是這個 gap）—— 這是唯一真正屬於你的部分。

把時間分配倒過來：**20% 寫 code，40% 建資料與實驗，40% 分析與寫作。**
